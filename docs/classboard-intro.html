01 Overview

从一块班牌，到一套班级日常

系统分成「教室大屏」和「管理后台」两条主线。终端面向学生，强调一眼可见、免登录、自动刷新；后台面向管理员，强调完整维护与审核闭环。

屏

教室大屏

2×4 等大模块卡片：公告、天气、签到、课表、食堂、新闻、歌单、班级生活。点击卡片弹出详情，30 秒自动轮询最新数据。

免密 通过 `/login` 选班或 `/terminal/{设备编码}` 自动绑定班级。
台

管理后台

12 个管理模块，覆盖公告、班级、课表、作业、设备、学生、签到、请假、新闻、点歌、食堂和班级生活。

安全 后台使用 Spring Security 表单登录，默认 `admin / admin123`。
库

数据与服务

15 张数据表、15 个 Repository、16 个 Service，配合天气、新闻和公告回收三个定时任务，把「展示」和「维护」连成闭环。

离线友好 天气/新闻失败时保留最近数据，班牌不会白屏。

06 Key Flows

四条最能体现业务闭环的流程

从刷卡到统计、从公告到倒计时、从点歌到已读确认、从定时同步到班牌刷新，系统把「写入」和「展示」串成了可演示的完整链路。

FLOW 01 · 考勤

刷卡签到 / 签退

  1. 读卡器模拟键盘输入卡号并回车，`CheckInView` 调用 `CheckInService`。
  2. 先查当天请假：请假学生提示「今日请假」，不产生签到记录。
  3. 第一次刷卡记到校，超过 07:30 标迟到；第二次记离校。
  4. 「应到」自动扣除当天请假人数，班牌与后台同步统计。
FLOW 02 · 公告

通知 → 倒计时 → 过期回收

  1. 后台发布公告，可填「相关日期」与「有效期至」。
  2. 相关日期进入班牌「班级生活」倒计时，同天同名自动去重。
  3. 有效期到点后查询立即过滤；后台状态显示「已过期」。
  4. 定时任务每小时把过期公告置为下线，保留历史记录。
FLOW 03 · 点歌

提交 → 审核 → 通知 → 确认

  1. 学生提交歌曲、歌手、点歌人与寄语，状态为「待审核」。
  2. 后台通过后进入今日歌单；驳回时填写原因，记录不删除。
  3. 点歌页顶部显示未读「审核通知」，包含原因和审核时间。
  4. 学生点击「已读确认」后从通知区消失，仍保留在本班记录。
FLOW 04 · 同步

天气 / 新闻定时更新

  1. 启动后定时任务拉取 Open-Meteo 未来三天天气。
  2. 新闻任务抓取新华网、人民网、中国教育新闻网教育列表。
  3. 结果写入 MySQL，班牌每 30 秒轮询读取最新数据。
  4. 外部接口失败时保留上次数据，不阻塞班牌展示。
ENGINEERING Details

工程细节：踩过的坑与修复

FIXEDVaadin 轮询不能设为 024.5 客户端会把 0 传给 `scheduleRepeating` 并抛异常；离开班牌时改为暂停轮询（1 小时间隔）。
FIXED自调用导致事务失效定时方法直接调用同类 `refresh()`，`@Transactional` 不生效；把事务注解放到定时方法上，天气恢复自动更新。
FIXEDMySQL 保留字冲突天气实体的 `condition` 是保留字；列名改为 `weather_condition`，避免建表失败。
FIXED浏览器插件伪路由`hybridaction/zybTrackerStatisticsAction` 会命中 404；增加 catch-all 路由，自动回到首页。
FIXED公告没有倒计时新增 `eventDate`，班级生活合并公告日期与独立倒计时，并按日期/名称去重。
FIXED驳回没有留存新增 `rejectReason` / `rejectReadAt`，驳回通知可保留、可确认已读，班牌只提示未读数。
07 Run & Deploy

一键启动，适合课堂演示

Windows 双击 `start.bat` 即可：检查 Java/Maven、启动 Spring Boot、等待就绪并自动打开浏览器。也支持手动 `mvn spring-boot:run`。

  1. 准备环境JDK 17、Maven 3.9+、MySQL 8（默认 3306，库不存在会自动创建）。
  2. 双击 start.bat脚本会检查环境、启动应用，并通过 `curl` 等待 8080 就绪后打开浏览器；`--no-browser` 可只启动。
  3. 进入班牌或后台访问 `/terminal/CB-A301-01` 直接进班牌，或 `/login` 选择班级 / 登录后台。
  4. 运行测试`mvn test` 执行 75 个单元测试；测试不连接数据库，不影响演示数据。

已知边界

课程项目优先保证演示完整与结构清晰，以下边界在 README 中也有说明：

  • 没有学生登录，点歌已读按班级共享
  • 单实例部署，多实例需要会话共享
  • 新闻依赖目标网站列表页结构
  • 图片保存在本机 uploads/
  • 请假按整天登记
  • 公告回收采用下线而非物理删除
